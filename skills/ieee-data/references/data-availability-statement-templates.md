# Data Availability Statement Templates

Use these four boilerplate variants after selecting a DOI-capable repository and confirming artifact restrictions. Replace bracketed fields only with author-supplied details.

## A. Open Code + Open Data

Data and code availability: The dataset, metadata, and analysis code supporting this study are openly available in [repository name] under DOI: [DOI]. The data are released under CC BY 4.0 (https://creativecommons.org/licenses/by/4.0/), and the code is released under [MIT / Apache-2.0 / BSD-3-Clause] as specified in the repository release record.

## B. Restricted Data

Data availability: The data supporting this study are subject to [privacy / consent / institutional / proprietary / third-party] restrictions and are not publicly downloadable. A metadata record and access instructions are available in [repository name] under DOI: [DOI]. Qualified researchers may request access through [data access committee, institutional office, or contact pathway] subject to [approval criteria or data-use agreement].

Code availability: The analysis code that can be shared without exposing restricted data is available in [repository name] under DOI: [DOI] and license [license]. Any scripts requiring restricted inputs are documented but cannot be executed without approved data access.

## C. No Data

Data availability: No datasets were generated or analyzed for this study. The manuscript reports [theoretical analysis / methodological description / survey / standards discussion], so there is no research dataset to deposit.

Code availability: No executable code artifact is required to reproduce the reported work. If auxiliary scripts are later added, they should be archived in a DOI-capable repository before submission.

## D. Hybrid: Some Open, Some Restricted

Data availability: The open portion of the data supporting this study is available in [repository name] under DOI: [DOI] and license [license]. The restricted portion, consisting of [restricted artifact description], cannot be publicly released because [restriction rationale]. Access to restricted data may be requested through [access pathway] subject to [approval criteria or data-use agreement].

Code availability: The analysis code and environment files are available in [repository name] under DOI: [DOI] and license [license]. The repository includes synthetic or sample inputs where restricted inputs cannot be distributed.
